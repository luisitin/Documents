Gotchas seen while installing (scaffold run):
- `expo-router` has `react-dom: *` as a peer; npm pulled `react-dom@19.3.1`, which then
  conflicts with `react@19.3.0` (ERESOLVE) on the next install. Fix: `npx expo install react-dom`
  pins 19.3.0, the same version the SDK 58 default template uses.
- `expo install` contacts api.expo.dev / reactnative.directory; set `EXPO_OFFLINE=1` to skip
  that and resolve from the bundled list only (same versions, "dependency validation unreliable").
- Opt a package out of version checks with `"expo": { "install": { "exclude": [...] } }` in package.json.
- SDK 58 default template also enables `"experiments": { "reactCompiler": true }` — optional.

## 2. Project structure for Expo Router 58 (docs: router/basics/*, router/reference/src-directory)

```
package.json           "main": "expo-router/entry"   (delete App.tsx / index.ts)
app.json               scheme, plugins, experiments.typedRoutes
tsconfig.json          extends expo/tsconfig.base, paths @/* -> ./src/*
eslint.config.js       generated by `npx expo lint` (flat config)
expo-env.d.ts, .expo/  generated by Expo CLI, git-ignored, never edit
src/app/_layout.tsx            root layout = old App.tsx (providers, fonts, splash)
src/app/(tabs)/_layout.tsx     <Tabs> navigator; (tabs) group does not appear in URLs
src/app/(tabs)/index.tsx       "/"  initial route (first index.tsx wins)
src/app/(tabs)/estimate.tsx    "/estimate"
src/app/(tabs)/settings.tsx    "/settings"
src/app/+not-found.tsx         unmatched routes
src/{components,db,i18n,lib,notifications,storage}/   non-route code (never inside src/app)
__tests__/*-test.ts(x)         tests (never inside src/app)
```

- `src/app` beats a root `app/` dir; config files stay in the project root.
- Only `.tsx` files in `src/app` are routes. `.android/.ios/.native/.web.tsx` variants inside
  `src/app` need a non-platform sibling. `/assets` is a reserved path.
- `app.json` minimum: `"scheme": "caatracker"`, `"plugins": ["expo-router", ...]`,
  `"experiments": { "typedRoutes": true }` (typed routes are still beta, not on by default).
  Use `Constants.expoConfig` at runtime; never import app.json. `newArchEnabled` is ignored (§11).
- No `babel.config.js` needed; `babel-preset-expo` already wires the Reanimated/worklets plugin.
- `npx create-expo-app@latest --template default@sdk-58` scaffolds this (plain `@latest` without
  `--template` still made an SDK 57 app during the transition window; Expo Go in the stores only
  supports one SDK — confirm expo.dev/go lists 58 before relying on Expo Go on a physical phone).

## 3. Minimal working layouts (type-checked, linted, bundled with `npx expo export`)

```tsx
// src/app/_layout.tsx
import '@/i18n';                                   // side effect: i18next ready before screens
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { Stack } from 'expo-router';
import { SQLiteProvider } from 'expo-sqlite';
import { Suspense } from 'react';
import { ActivityIndicator } from 'react-native';
import { migrateDbIfNeeded } from '@/db/migrations';

export { ErrorBoundary } from 'expo-router';        // route-tree error boundary
const queryClient = new QueryClient();

export default function RootLayout() {
  return (
    <QueryClientProvider client={queryClient}>
      <Suspense fallback={<ActivityIndicator style={{ flex: 1 }} />}>
        <SQLiteProvider databaseName="caa-tracker.db" onInit={migrateDbIfNeeded} useSuspense>
          <Stack>
            <Stack.Screen name="(tabs)" options={{ headerShown: false }} />
          </Stack>
        </SQLiteProvider>

```

Alternative: native tabs (`import { NativeTabs } from 'expo-router/native-tabs'` — stable entry
point in SDK 58; `NativeTabs.Trigger` + `.Label`/`.Icon sf= md=`). The SDK 58 default template
renders native tabs via `src/components/app-tabs.native.tsx` and custom `expo-router/ui` tabs on web.

Navigation rules (router/basics/navigation, migrate/sdk-57-to-58):
- `const router = useRouter(); router.push('/estimate')` / `router.navigate` / `replace` / `back`.
  Module-level `router` throws before first render; prefer the hook.
- `<Link href="/settings">`, `<Link href={{ pathname: '/case/[id]', params: { id } }}>`; typed
  routes reject typos; relative hrefs are not typed. `<Link asChild><Pressable/></Link>` for buttons.
- `useLocalSearchParams<{ filedOn?: string }>()` for query params (not derivable from files).
- Deep-link back-stack: `export const unstable_settings = { anchor: 'index' }` in the stack layout.
- Stack-inside-tab: `src/app/(tabs)/feed/_layout.tsx` returns `<Stack/>`; push detail screens
  from the root stack if "back" should return to the originating tab.
- Push-notification deep links: in the root layout read `getLastNotificationResponse()` +
  `addNotificationResponseReceivedListener`, `router.push(data.url)`, then
  `clearLastNotificationResponse()`.

## 4. i18n bootstrap (expo-localization 58 + i18next 26 + react-i18next 17)

```ts
// src/i18n/index.ts
import { getLocales } from 'expo-localization';   // sync; list always has >= 1 entry
import { createInstance } from 'i18next';
import { initReactI18next } from 'react-i18next';
import { kv } from '@/storage/kv';
import en from './locales/en.json';
import es from './locales/es.json';

export const resources = { en: { translation: en }, es: { translation: es } } as const;
const saved = kv.get('language');
const deviceLanguage = getLocales()[0]?.languageCode ?? 'en';

export const i18n = createInstance({
  resources,
  lng: saved ?? deviceLanguage,
  fallbackLng: 'en',
  interpolation: { escapeValue: false },
});
void i18n.use(initReactI18next).init();
export default i18n;
```

```ts
// src/i18n/i18next.d.ts — typed t('tabs.dashboard')
import 'i18next';
import type { resources } from './index';
declare module 'i18next' {
  interface CustomTypeOptions { defaultNS: 'translation'; resources: (typeof resources)['en'] }
}
```

- Usage: `const { t, i18n } = useTranslation(); t('estimate.window', { from, to }); i18n.changeLanguage('es')`.
- `createInstance()` instead of `import i18n from 'i18next'; i18n.use(...)` because
  `eslint-config-expo` warns (`import/no-named-as-default-member`) on the default-import form, and
  the named `use` export is an *unbound* method (`const use = instance.use`) — do not call it bare.
- Per-app language in system settings: `["expo-localization", { "supportedLocales": ["en","es"] }]`
  plugin (needs a dev build to take effect; harmless in Expo Go).
- Android can change locale without restart: re-run `getLocales()` on `AppState` → active. iOS restarts the app.
- Format dates/numbers with `Intl` (Hermes supports it): `new Intl.DateTimeFormat('default', {...})`.
- `expo-localization` exports only `getLocales/getCalendars/useLocales/useCalendars` + types.
  `Localization.locale` / `Localization.region` no longer exist.

## 5. Storage: expo-sqlite (yes) vs MMKV (no) — docs sdk/sqlite, react-native-mmkv README

Decision: **expo-sqlite** for the offline cache of USCIS snapshots + **`expo-sqlite/kv-store`**
for settings. Both run in Expo Go, one native dependency, sync KV API available.
- `react-native-mmkv` 4.x is a Nitro Module: peer `react-native-nitro-modules`, README install is
  `npx expo install react-native-mmkv react-native-nitro-modules && npx expo prebuild` → requires a
  development build (nitro is not in `bundledNativeModules.json`). Revisit only if a dev build is
  already mandatory and KV speed matters. (*New-Architecture support: inferred from "JSI + Nitro".*)
- AsyncStorage 2.2.0 is in Expo Go but redundant: `import Storage from 'expo-sqlite/kv-store'` has
  the same API plus `getItemSync/setItemSync`.

```ts
// src/db/migrations.ts — onInit for <SQLiteProvider>, versioned with PRAGMA user_version
import type { SQLiteDatabase } from 'expo-sqlite';
const DATABASE_VERSION = 1;
export async function migrateDbIfNeeded(db: SQLiteDatabase) {
  const row = await db.getFirstAsync<{ user_version: number }>('PRAGMA user_version');
  let current = row?.user_version ?? 0;
  if (current >= DATABASE_VERSION) return;
  if (current === 0) {
    await db.execAsync(`PRAGMA journal_mode = 'wal';
      CREATE TABLE IF NOT EXISTS snapshots (id INTEGER PRIMARY KEY NOT NULL, period TEXT NOT NULL UNIQUE,
        pending INTEGER NOT NULL, approved INTEGER NOT NULL, denied INTEGER NOT NULL, fetched_at TEXT NOT NULL);`);
    current = 1;
  }
  await db.execAsync(`PRAGMA user_version = ${DATABASE_VERSION}`);
}
```

```ts
// in a screen
const db = useSQLiteContext();
const { data = [] } = useQuery({ queryKey: ['snapshots'], queryFn: () => db.getAllAsync<Snapshot>('SELECT * FROM snapshots ORDER BY period') });
await db.runAsync('INSERT INTO snapshots (...) VALUES ($period, $pending, ...)', { $period, $pending }); // named params
const rows = await db.sql<Snapshot>`SELECT * FROM snapshots WHERE pending > ${min}`;              // tagged template, auto-escaped
await db.withExclusiveTransactionAsync(async (txn) => { /* only queries in here join the txn */ });
```

API cheat: `openDatabaseAsync(name)` (no `openDatabase`), `execAsync` (bulk, no params, no
escaping), `runAsync` → `{ lastInsertRowId, changes }`, `getFirstAsync`, `getAllAsync`,
`getEachAsync` (cursor), `prepareAsync` + `executeAsync` + `finalizeAsync` in `try/finally`,
`withTransactionAsync` (any concurrent query joins it — prefer `withExclusiveTransactionAsync`).
Enable WAL once. Inspector: press Shift+M in `expo start`, "Open expo-sqlite". `useSQLCipher`
needs a dev build; libSQL sync was removed in 58.0.0. Web needs the metro wasm config (not needed here).

## 6. Notifications caveats (docs sdk/notifications, push-notifications/*, dev-builds FAQ)

- **Remote push does not work in Expo Go** ("You must use a development build"; Android dropped it
  in SDK 53, iOS is not supported either). Local/scheduled notifications work in Expo Go.
- Foreground handler (SDK 58 breaking change: foreground notifications are shown by default
  unless a handler says otherwise):
  `setNotificationHandler({ handleNotification: async () => ({ shouldShowBanner: true, shouldShowList: true, shouldPlaySound: false, shouldSetBadge: false }) })`
  — `shouldShowAlert` is `@deprecated`.
- Triggers are discriminated objects: `{ type: SchedulableTriggerInputTypes.TIME_INTERVAL, seconds: 5, channelId: 'default' }`,
  `DATE`, `DAILY`, `WEEKLY`, `CALENDAR`; `trigger: null` shows immediately. Android 12+ exact-time
  triggers need `SCHEDULE_EXACT_ALARM` (`requestExactAlarmPermissionsAsync`).
- Android: create a channel (`setNotificationChannelAsync('default', { name, importance: AndroidImportance.DEFAULT })`)
  **before** `requestPermissionsAsync` (Android 13 prompt) and before any token call.
  iOS: read `permissions.ios.status` (`IosAuthorizationStatus`) rather than the root status.
- Push token: `getExpoPushTokenAsync({ projectId })` with
  `projectId = Constants.expoConfig?.extra?.eas?.projectId ?? Constants.easConfig?.projectId`
  (set by `eas build:configure` / `eas init`). Credentials: FCM V1 (Android), APNs key (paid Apple
  account) managed by `eas credentials`/first `eas build`. Send via `https://exp.host/--/api/v2/push/send`
  or the expo.dev/notifications tool. Background data-only pushes additionally need `expo-task-manager`
  + `enableBackgroundRemoteNotifications: true` in the plugin.
- Config plugin: `["expo-notifications", { "icon": "./assets/notification-icon.png" (96x96 white/transparent), "color": "#...", "defaultChannel": "default", "enableRemoteNotifications": true }]` — build-time only.
- Listeners return subscriptions; clean up with `sub.remove()` (`removeNotificationSubscription` no longer exists).
- Lint gotcha (verified): `Notifications.AndroidImportance.MAX` on a namespace import trips
  `import/namespace` in eslint-config-expo 58. Use named imports:
  `import { AndroidImportance, scheduleNotificationAsync, ... } from 'expo-notifications'`.

## 10. New Architecture / platform defaults (docs guides/new-architecture, versions/v58 index, sdk-58-beta changelog)

- SDK 55+ **always** runs the New Architecture; `newArchEnabled: false` is ignored. Expo Go is New-Arch only.
- All `expo-*` packages support it; third-party status is checked by `npx expo-doctor` (React Native Directory).
- SDK 58 = React Native 0.88 + React 19.3; targets iOS 27 (UIKit scene life cycle — only matters if
  you customize AppDelegate); the bare template now enables R8 minification for Android release builds; TypeScript 6.0.
- Interop layer covers most old-arch libraries, but libraries shipping native code may need updates.

## 12. Common LLM mistakes in SDK 58 (wrong → correct)

1. `App.tsx` + `registerRootComponent` → `"main": "expo-router/entry"` and `src/app/_layout.tsx`.
2. Routes in root `app/` → `src/app/` (template default since SDK 55; `src/app` wins if both exist).
3. `expo-router/unstable-native-tabs` → `expo-router/native-tabs` (stable in 58).
4. `<Stack initialRouteName="index">` → `export const unstable_settings = { anchor: 'index' }`.
5. Tabs auto-discovering routes → every tab must be a `<Tabs.Screen>`/`NativeTabs.Trigger`; hide with `href: null`.
6. `navigation.navigate('(tabs)', { screen: 'feed', params })` → `router.push({ pathname: '/(tabs)/feed/[id]', params })`.
7. `<Stack.Screen redirect / initialParams>` → `<Redirect href>` in the route / `Stack.Protected guard redirectTo` / defaults in `useLocalSearchParams`.
8. `freezeOnBlur` → `activityEnabled`; `withLayoutContext` → `integrateWithRouter` (deprecated alias still works).
9. Importing `@react-navigation/*` in app code → not supported since SDK 56; use `expo-router` entry points (`DarkTheme`, `ThemeProvider`, `useNavigation`, ...).
10. Module-level `router.push` at import time → throws before first render; use `useRouter()`.
11. `@expo/vector-icons` "comes with expo" → it is **not** a dependency any more; `npx expo install @expo/vector-icons` (15.x). Its `color` prop rejects RN's `ColorValue` (`number|null`), so with `tabBarIcon` prefer `expo-symbols` `SymbolView` (`tintColor: ColorValue`, cross-platform `name={{ ios, android, web }}`).
